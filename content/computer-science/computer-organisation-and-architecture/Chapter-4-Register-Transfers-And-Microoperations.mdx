## Introduction

How does a modern computer execute billions of complex tasks every second using nothing more than millions of tiny digital switches? The secret lies in a tightly coordinated dance of microscopic data movements known as microoperations, directed by a concise symbolic blueprint called Register Transfer Language.

In this lesson, you will explore the foundational mechanics of internal hardware architecture. By the end of this journey, you will be able to:

- **Analyze and interpret** Register Transfer Language (RTL) notation and control functions.
- **Evaluate** the construction and operation of common bus structures and memory transfer paths.
- **Design and trace** key hardware circuits for arithmetic, logic, and shift microoperations.
- **Understand** the unified architecture of a complete Arithmetic Logic Shift Unit (ALU).
- **Identify** how Hardware Description Languages (HDLs) like VHDL model these hardware operations in modern engineering.

## Register Transfer Language

At the core of any digital system lies a collection of interconnected hardware modules—registers, decoders, arithmetic units, and control logic. To make sense of how data flows through these components, we focus on **microoperations**: elementary operations performed on binary data stored within registers. Common examples of microoperations include clearing a register, incrementing a count, loading new data, or shifting bits to the left or right.

Describing every tiny hardware movement in plain narrative prose would quickly become overwhelming and wordy. To solve this, computer architects use **Register Transfer Language (RTL)**—a precise, symbolic notation that concisely expresses the exact sequences of transfers and operations occurring between registers.

To fully define the internal hardware organization of a digital computer, three primary specifications are required:

1. **The set of registers** present and their designated functions.
2. **The sequence of microoperations** executed on the binary data stored in those registers.
3. **The control signals** that initiate and synchronize each sequence of microoperations.

Just as programmers use high-level programming languages to define abstract computational algorithms, hardware designers use RTL to specify the physical flow of data through logic circuits.

## Register Transfer

In digital system diagrams, registers are represented by simple rectangular boxes designated by capital letters (and sometimes numbers) reflecting their specific function. For instance, **MAR** stands for Memory Address Register, **PC** denotes the Program Counter, **IR** represents the Instruction Register, and **R1** signifies a general processor register.

Bits inside an $n$-bit register are numbered sequentially from right to left, starting at bit `0` for the least significant bit up to $n-1$ for the most significant bit. A 16-bit register like **PC** can also be partitioned into two 8-bit bytes: **PC(L)** or **PC(0–7)** for the low-order byte, and **PC(H)** or **PC(8–15)** for the high-order byte.

Information transfer from a source register to a destination register is written using a leftward arrow replacement operator:

$$
R2 \leftarrow R1
$$

This statement means the contents of **R1** are copied into **R2**. Crucially, the contents of the source register **R1** remain completely unchanged.

In hardware, transfers usually happen under specific conditional circumstances. We express these conditions using **control functions**—Boolean variables terminated by a colon:

$$
P: R2 \leftarrow R1
$$

This statement specifies that if control variable $P = 1$, the hardware transfers the data from **R1** to **R2**. In physical circuitry, the $n$ outputs of register **R1** connect directly to the inputs of register **R2**, while control signal $P$ connects to **R2**'s parallel `Load` input. The transfer occurs synchronously on the rising edge of the system clock. If two operations occur simultaneously during the exact same clock pulse, they are separated by a comma:

$$
T: R2 \leftarrow R1, R1 \leftarrow R2
$$

Because edge-triggered flip-flops are used, this statement cleanly swaps the contents of **R1** and **R2** in a single clock cycle without data corruption!

## Bus and Memory Transfers

Imagine a processor with dozens of internal registers. Connecting dedicated physical wires between every pair of registers would create a tangled maze of millions of connections! To eliminate this bottleneck, digital systems use a **common bus system**—a shared set of parallel lines that transfers binary data one register at a time.

### Multiplexer-Based Bus Systems

One common way to build a shared bus is using multiplexers (MUXes). For a system with $k$ registers of $n$ bits each, the bus requires $n$ multiplexers of size $k \times 1$. For example, a 4-register bus where each register is 4 bits wide requires four $4 \times 1$ MUXes. Two selection lines ($S_1, S_0$) select which register's 4-bit output is placed onto the 4-line bus:

- $S_1S_0 = 00 \rightarrow \text{Register A}$
- $S_1S_0 = 01 \rightarrow \text{Register B}$
- $S_1S_0 = 10 \rightarrow \text{Register C}$
- $S_1S_0 = 11 \rightarrow \text{Register D}$

### Three-State Bus Buffers

Alternatively, a bus can be constructed using **three-state buffer gates**. Unlike standard logic gates that output only `0` or `1`, a three-state buffer features a third state: a **high-impedance state** ($Hi-Z$). In $Hi-Z$, the output acts like an open circuit—effectively disconnecting the gate from the wire. By using a decoder to ensure that only _one_ buffer is active while all others remain in high-impedance mode, multiple outputs can safely connect directly to the same bus wire without signal interference.

### Memory Transfers

Transferring data between registers and external memory involves **Read** and **Write** microoperations. We symbolize a memory word by the letter $M$, with its address enclosed in square brackets:

- **Memory Read**: $DR \leftarrow M[AR]$ _(Data from memory location specified by Address Register AR is loaded into Data Register DR)_
- **Memory Write**: $M[AR] \leftarrow R1$ _(Contents of register R1 are stored into memory at location AR)_

## Arithmetic Microoperations

While register transfers simply move data without altering it, **arithmetic microoperations** transform numeric data through basic arithmetic routines like addition, subtraction, incrementing, and decrementing.

### Binary Adder and Subtractor Circuits

Addition is the primary building block for computer arithmetic. An $n$-bit **binary adder** is constructed by cascading $n$ full-adder (FA) circuits, passing the carry output from each bit position to the carry input of the next higher bit position.

To perform subtraction ($A - B$), hardware designers utilize 2's complement arithmetic:

$$
A - B = A + \bar{B} + 1
$$

By adding an Exclusive-OR (XOR) gate to each $B$ input of a binary adder and controlling it with a mode selection signal $M$, we create a versatile **binary adder-subtractor**:

- When $M = 0$: The XOR gates pass $B$ unchanged and $C_0 = 0$, executing $A + B$.
- When $M = 1$: The XOR gates invert $B$ to produce its 1's complement ($\bar{B}$) and $C_0 = 1$, executing $A + \bar{B} + 1$ (subtraction!).

### 4-Bit Composite Arithmetic Circuit

We can combine multiple arithmetic operations into a single combinational circuit using parallel adders driven by multiplexers. By altering the inputs $Y$ to a 4-bit adder via selection lines $S_1$ and $S_0$ along with an input carry $C_{in}$, a single circuit generates eight distinct operations:

1. $S_1S_0 = 00, C_{in} = 0$: $D = A + B$ (Add)
2. $S_1S_0 = 00, C_{in} = 1$: $D = A + B + 1$ (Add with carry)
3. $S_1S_0 = 01, C_{in} = 0$: $D = A + \bar{B}$ (Subtract with borrow)
4. $S_1S_0 = 01, C_{in} = 1$: $D = A $ $+ \bar{B} + 1$ (Subtract)
5. $S_1S_0 = 10, C_{in} = 0$: $D = A$ (Transfer $A$)
6. $S_1S_0 = 10, C_{in} = 1$: $D = A + 1$ (Increment $A$)
7. $S_1S_0 = 11, C_{in} = 0$: $D = A - 1$ (Decrement $A$)
8. $S_1S_0 = 11, C_{in} = 1$: $D = A$ (Transfer $A$)

## Logic Microoperations

Unlike arithmetic microoperations that treat bit vectors as complete numeric values, **logic microoperations** perform bitwise manipulations on strings of binary data, treating each pair of bits independently.

While there are 16 possible Boolean logic operations for two variables, most computers implement four fundamental microoperations: **AND** ($\wedge$), **OR** ($\vee$), **XOR** ($\oplus$), and **Complement** (1's complement). A single stage of a logic circuit uses gates for each operation feeding into a $4 \times 1$ MUX with selection lines $S_1, S_0$.

### Practical Applications of Logic Microoperations

Logic microoperations are crucial tools for bit manipulation in processor software:

- **Selective-Set (**$A \leftarrow A \vee B$**)**: Sets bits in register $A$ to `1` wherever corresponding bits in $B$ are `1`, leaving all other bits intact.
- **Selective-Complement (**$A \leftarrow A \oplus B$**)**: Inverts bits in register $A$ wherever corresponding bits in $B$ are `1`.
- **Selective-Clear (**$A \leftarrow A \wedge \bar{B}$**)**: Clears bits in $A$ to `0` wherever corresponding bits in $B$ are `1`.
- **Mask Operation (**$A \leftarrow A \wedge B$**)**: Clears bits in $A$ to `0` wherever corresponding bits in $B$ are `0` (retaining $A$'s bits where $B$ contains `1`s).
- **Insert Operation**: Replaces a bit field by first applying a **Mask** operation to zero out target bit positions, then performing an **OR** operation to insert the new bit patterns.
- **Clear / Compare (**$A \leftarrow A \oplus B$**)**: Compares two words; if identical, the operation returns all `0`s.

## Shift Microoperations

Shift microoperations move stored binary data laterally to the left or right inside a register. They are essential for serial data transfers, byte packing, and fast arithmetic.

### Three Types of Shifts

1. **Logical Shift**: Shifts data bits sideways while shifting a `0` into the empty end position. Written as `shl R` (shift-left) or `shr R` (shift-right).
2. **Circular Shift (Rotate)**: Circulates bits around the register's opposite ends without losing any information. Written as `cil` (circular shift-left) or `cir` (circular shift-right).
3. **Arithmetic Shift**: Shifts signed binary numbers left or right without altering the sign bit ($R_{n-1}$).
   - **Arithmetic Shift-Right (\*\***ashr\***\*)**: Divides a signed number by 2. The sign bit $R_{n-1}$ remains unchanged, $R_{n-2}$ receives $R_{n-1}$, and the least significant bit is discarded.
   - **Arithmetic Shift-Left (\*\***ashl\***\*)**: Multiplies a signed number by 2 by shifting bits left and inserting `0` into bit `0`. If bit $R_{n-1}$ changes value, a sign reversal and arithmetic overflow occur! An overflow flip-flop detects this condition using the Boolean test:
     $$
     V_s = R_{n-1} \oplus R_{n-2}
     $$

### Hardware Implementation

Instead of using shift registers that require multiple clock cycles, processors use **combinational shifters** built from multiplexers. A combinational shifter can shift an entire $n$-bit register in a single clock cycle as data passes through the bus structure.

## Arithmetic Logic Shift Unit

Instead of building distinct hardware logic and registers for every isolated microoperation, computer systems consolidate arithmetic, logic, and shift functions into a single shared processing block called the **Arithmetic Logic Unit (ALU)**.

### Unified ALU Stage Architecture

A full $n$-bit ALU is constructed by repeating a single hardware stage $n$ times. Each stage receives input bits $A_i$ and $B_i$, alongside stage carries $C_i$, and routes data through three unified functional branches:

1. **Arithmetic Section**: Calculates arithmetic sums ($E_i$).
2. **Logic Section**: Computes bitwise logic operations ($H_i$).
3. **Shift Section**: Receives neighboring bits $A_{i+1}$ (for shift-right) and $A_{i-1}$ (for shift-left).

A $4 \times 1$ output multiplexer uses master selection lines $S_3$ and $S_2$ to choose whether to output an arithmetic result, a logic result, a right-shifted bit, or a left-shifted bit into output $F_i$.

Across the entire unit, 5 control inputs ($S_3, S_2, S_1, S_0, C_{in}$) determine the specific function executed. Together, they select from **14 distinct microoperations**: 8 arithmetic operations, 4 logic operations, and 2 shift operations—all calculated in a single clock pulse period.

## Hardware Description Languages

Designing complex digital processors at the manual gate and flip-flop level is painstaking and prone to human error. Modern computer engineering relies on **Hardware Description Languages (HDLs)** to design, simulate, and debug digital logic at the register transfer level before translating designs into silicon.

The two predominant standard HDLs are **VHDL** (VHSIC Hardware Description Language) and **Verilog**. Unlike programming languages like C++ that execute serial commands on a CPU, HDLs describe parallel hardware structures that exist concurrently in physical gates.

### Basic VHDL Framework

In VHDL, any hardware block is divided into two fundamental components:

1. **ENTITY**: Defines the input/output (I/O) interface and signal ports of the hardware component without describing internal logic.
2. **ARCHITECTURE**: Defines the internal behavior, logic equations, and structural connections of the component.

For example, an 8-bit comparator is declared as follows:

```
library ieee;
use ieee.std_logic_1164.all;

ENTITY compare8 IS
  PORT(
    x, y : IN  std_logic_vector(7 DOWNTO 0);
    res  : OUT std_logic
  );
END compare8;

ARCHITECTURE struct OF compare8 IS
BEGIN
  res <= '1' WHEN (x = y) ELSE '0';
END struct;
```

Here, `std_logic_vector(7 DOWNTO 0)` specifies an 8-bit bus, and the architecture conditionally asserts `res <= '1'` whenever all 8 bits of vector `x` match vector `y`.

## Summary

Register Transfer Language provides the foundation for computer hardware architecture, offering a precise symbolic framework for describing how microoperations transform and route binary data through registers, common bus structures, arithmetic logic units, and modern HDL hardware descriptions.

### Key Takeaways

- **Register Transfer Language (RTL)** uses concise symbolic notation (e.g., $P: R2 \leftarrow R1$) to define hardware transfers and control conditions synchronized by system clock edges.
- **Bus Systems** reduce interconnect overhead using $k \times 1$ multiplexers or three-state buffer gates with high-impedance capability to share common transmission lines.
- **Arithmetic Microoperations** execute numeric functions (Add, Subtract, Increment, Decrement) using full-adder cascades, XOR mode logic, and input carry controls.
- **Logic Microoperations** perform bitwise operations used for selective manipulation techniques such as masking, setting, clearing, and inserting bit patterns.
- **Shift Microoperations** move data laterally across registers via logical, circular, or sign-preserving arithmetic shifts with built-in overflow detection ($V_s = R_{n-1} \oplus R_{n-2}$).
- **Arithmetic Logic Shift Units (ALUs)** synthesize arithmetic, logic, and shift circuits into unified processing blocks governed by master control selection lines.
- **Hardware Description Languages (VHDL/Verilog)** model register transfer operations in software, using decoupled `ENTITY` interfaces and `ARCHITECTURE` logic descriptions.
